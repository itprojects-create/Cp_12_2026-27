## 8. Bottom line (as-is, no M4 reach)

- The gate **fixed the trade-rate breach** (0.917→0.75, 0.958→0.75, back in
  bounds) exactly as scoped — but **accuracy fell on both sets** (0.385→0.231,
  0.5→0.333). The fall is NOT the gate's doing (gated sessions went 2 OK / 1
  real cost / rest loss-reduced-or-neutral): with n_decisive=12–13, the edited
  manager prompt + fresh sids re-sampled several theses (TCS#1 and ICICI#7 went
  flat; EICHERMOT went flat), and 2 flips swing the headline. That sampling
  sensitivity at n≈12 is itself the finding: **single-run accuracy here is
  noise-dominated, and the gate trades one error type for another**
  (SBIN: a correct momentum long blocked in STRESSED).
- The "more holds" came mostly from **flat theses (5 new-24, 3 orig-24), not the
  gate (2 and 6 sessions, mostly halves)**. M3 is a working, audited guardrail
  with a measured, bounded effect — not the fix for direction quality.
- Expected and informative per the task: the gate alone doesn't fix accuracy or
  calibration. Next, in order: (1) fresh third scenario set before citing
  numbers; (2) M2 slice-depth + threshold loosening (Part 0 shows 25% fire at
  80th vs 8% at 90th, and production never even reaches the ticker-own
  distribution); (3) M4 only after those. No M4 work was touched this round.
